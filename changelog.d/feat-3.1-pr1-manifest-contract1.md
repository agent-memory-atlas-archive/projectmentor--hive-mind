- **3.1: module manifest contract 1.** A signed `module.json` may now declare `"contract": 1` and the optional fields `cli`, `runtimes`, `config_schema` (replacing `config`), `status`, `doctor`, `reads` and `ui`; the validator refuses a malformed field, a contract-1 field without `contract`, an unknown `contract`, a `min_core` below 3.1, and a default on an `identifying` or `secret` config key. A manifest without `contract` is accepted unchanged. New `hive-mind module check <dir> [--run] [--deny TERM] [--json]` runs the same validator for publishers and CI, lints shipped files for identifying text (warnings only), and with `--run` checks the `status` and `doctor` shapes in a throwaway directory. `docs/ui_block.schema.json` defines the `ui` block. `CONTRACT_VERSION` is `3.1` (additive: no adapter-facing verb changes); a 3.0 node refuses a contract-1 manifest as unknown fields. The core validates these fields now; the behaviour that acts on them (config schema, runtimes and the CLI launcher, the module doctor, read routes) lands in the PRs that follow.
